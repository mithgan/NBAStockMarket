# Databallr historical player identities

`app/src/data/playerHistoryPlayers.ts` exports the explicit crosswalk used by historical profiles. It contains identity only. Player history is fetched on demand from the existing Databallr API.

## Verification

Checked at 2026-09-28T20:25:07.164684+00:00.

All requests used public GETs with system-TLS-validated curl; no credentials or user token were sent. The audit capped concurrency at 3. Each listed player received one search, one info lookup and one 2024–25 gamelog request limited to 200 rows. Luka and Kon also received one latest-season request limited to 1 row. No full latest-season download was performed.

The production list in `data/generated/market-seed.json` and the demo list in `app/src/data/snapshot.ts` both contain the same 30 ID/name pairs. Each mapping was derived from an exactly matching normalized `player_name` in Databallr search, with exactly one match, then independently confirmed using the resulting `nba_id` on player-info. Search results never reached the default limit of 20. Normalization applies Unicode NFKD, removes diacritics, lowercases, and removes characters other than ASCII letters/digits. No ID equality, fuzzy match, team match or numeric guess was used.

The historical response must independently match the expected NBA ID, normalized name, end year and regular-season flag. Empty data does not invalidate identity. Unmapped IDs and mismatched names must return an honest unavailable state; they must never fall back to using the ESPN ID as an NBA ID.

## Endpoint interpretation and missing data

The existing `/v1/nba/players/gamelog` route filters by NBA ID, optional end year and playoffs, orders by descending date and passes through the `nbagamelog` rows. It returns an array; the default row limit is 100, so this profile explicitly requests 200. All 30 checked responses were HTTP 200 and below that cap. The 29 nonempty players produced 1,840 rows in total. There were no malformed core stats, duplicate dates, identity mismatches, or zero-minute rows in this audit. Kon Knueppel is mapped but returned an empty 2024–25 season.

All 1,840 checked 2024–25 rows have `Opponent: null`; none supplies a provider game ID or venue field. Keep opponent and home/away unknown for those records. Do not infer an opponent from team, date or local replay fixtures. The limited 2025–26 probes show that `Opponent` can be populated in newer data.

`date` is a numeric `YYYYMMDD`. `MIN` is decimal minutes and must remain numeric without a decimal-seconds reinterpretation. Established monorepo use is explicit: `apps/web/src/components/lastgames/statUtils.ts` (`legacyGameLogToNormalized`) parses `MIN` unchanged and uses it directly in per-36 calculations; `apps/web/src/components/lastgames/types.ts` (`convertMinutesToDecimal`) leaves numeric values unchanged and converts only colon-separated clock strings. The API's `apps/api/src/bdl-gamelogs-shared.ts` (`parseMinutesToDecimal`) follows the same convention. These paths are under the adjacent `stock-market-integration-20260918` checkout. For example, Luka's first returned prior-season game has `MIN: 36.2783333333333` on `20241024`, with 28 points, 10 rebounds and 8 assists. Preserve the source precision for totals/averages, and round only for display.
